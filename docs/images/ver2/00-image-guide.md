# Ver2 Note記事用画像

記事タイトル案：

> 電話対応を減らす予約サイトを作った話②｜予約から配車・回収までつなげました

## 掲載順

1. `01-admin-dispatch-overview.png`
   - 掲載位置：「予約管理から、配車・回収管理へ広げる」の後
   - キャプション：予約状況と配車・回収状況をまとめて確認できる管理画面
   - 代替テキスト：予約件数、配車状況、警告、カレンダーを表示した予約・配車管理画面

2. `02-dispatch-editor.png`
   - 掲載位置：配車登録の説明の後
   - キャプション：予約詳細を確認しながら予定日時、車両、主担当ドライバーを登録
   - 代替テキスト：予定日時、車両、主担当ドライバーを入力する配車登録欄

3. `03-vehicle-management.png`
   - 掲載位置：ドライバー・車両登録の説明の後
   - キャプション：車両ナンバー、車種、積載参考情報、利用状態を管理
   - 代替テキスト：登録車両の車両コード、ナンバー、車種、車両保留を一覧表示した車両管理画面

4. `04-driver-assignment.png`
   - 掲載位置：ドライバー画面の説明の後
   - キャプション：担当期間を指定し、案件の詳細と作業に必要な情報を確認
   - 代替テキスト：担当案件一覧と選択した回収案件の詳細を表示したドライバー画面

5. `05-collection-outcome.png`
   - 掲載位置：「全量回収・一部回収・回収できず」の説明の後
   - キャプション：現場の実情に合わせて3種類の回収結果と次回対応を記録
   - 代替テキスト：全量回収、一部回収、回収できずを選択する作業結果登録画面

## 選定方針

- 5枚すべてを使うと、管理者の確認から配車、車両管理、ドライバー確認、回収結果までの流れが伝わります。
- 記事を短く見せたい場合は、`03-vehicle-management.png`を省いた4枚構成にします。
- 画像内の会社名・氏名・住所・電話番号・車両ナンバーは、公開デモ用の架空データです。
