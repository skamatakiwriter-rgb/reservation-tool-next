## 1. 文書の目的

本書は、`14_予約管理ツール_Ver2_配車・回収管理基本設計書.md`で定めたVer2の業務ルールを、画面、表示項目、操作、入力条件、状態遷移へ落とし込む。

本書では、主に次を定める。

- Ver1画面へ追加するVer2の導線と表示
- 予約一覧・予約詳細へ統合する配車状況、依頼内容確認、配車登録・変更
- ドライバー画面の担当確認、任意の回収開始記録、作業結果登録
- 一部回収、回収不可、再配車の画面上の扱い
- 同日中に同じ車両・同じ主担当ドライバーで回収を続ける場合の無操作ルール
- 保存失敗、競合、空状態、スマートフォン表示

データ項目の型、IndexedDBのストア構成、トランザクションの詳細は、次工程のVer2データ・保存詳細設計書で定める。

## 2. 適用範囲と仕様の優先順位

- Ver1の既存画面仕様は`02_予約管理ツール_画面仕様書.md`を維持する。

## 4. 共通表示

### 4.1 デモ表示

Ver2の管理系画面には、次を常時確認できるデモ案内として表示する。

- 公開デモであること
- 架空データだけを使用すること
- 同じブラウザ内だけに保存されること
- 本番認証、複数端末共有、通知、GPS、経路最適化がないこと

### 4.2 状態表示

状態は色だけで区別せず、必ず文字を併記する。

| 区分 | 表示 |
|---|---|
| 予約状態 | 受付、確定、完了、取消 |
| 配車状態 | 未配車、配車済み、回収中、作業終了、配車取消 |
| 作業結果 | 全量回収、一部回収、回収できず |
| 注意状態 | 要再配車、要対応、要再確認 |

「一部回収」には、必要に応じて「今回の配車は終了・残りあり」という補助文を表示し、作業途中の積み込みと誤解させない。

### 4.3 日時・操作者

- 日付は画面上で`YYYY年M月D日`を基本とする。
- 時刻は24時間表記の`HH:mm`とする。
- 履歴と社内補足には記録日時と操作者を併記する。
- 保存直前の端末日時を使用し、利用者が作成日時を手入力しない。

### 4.4 共通ナビゲーション

共通ヘッダーに使い方ガイドとデモデータ管理への導線を置く。各画面には短い「この画面の使い方」を折り畳み表示し、詳しいガイドの該当箇所へ移動できるようにする。管理画面の短い案内と詳しいガイドでは、初めて使う人を前提に、数量の変更先、連絡事項との違い、配車前の変更では注意表示が出ず、配車後の重要変更で初めて橙色の注意書きと「要再確認」が出る理由を、操作順に沿って説明する。ただし、予約確定前の配車不可等の重要な業務ルールは折り畳み内だけに置かず、該当操作の近くへ常時表示する。

管理系画面のヘッダーに、少なくとも次の導線を置く。

- 予約管理
- デモ入口へ戻る

ドライバー画面には、担当案件一覧へ戻る導線とデモ入口へ戻る導線を置く。スマートフォンでもブラウザの戻る操作だけに依存しない。

## 5. デモ入口 `/`

### 5.1 追加表示

Ver1の利用者用・管理者用入口を残す。管理者用入口の説明をVer2の予約・配車管理まで含む内容へ更新し、次の入口を追加する。

| 入口 | 説明 | 遷移先 |
|---|---|---|
| ドライバーデモ | 本日の担当、回収開始、作業結果を確認する | `/driver` |
| 使い方ガイド | 予約、配車、ドライバーのおすすめ確認順序と画面別の操作を確認する | `/guide` |
| デモデータ管理 | ブラウザ内の保存データを初期状態へ戻す、または削除する | `/demo-data` |

Ver1とVer2を混同しないよう、「Ver1：予約管理」「Ver2：配車・回収管理」の区分を表示する。

### 5.2 デモデータ管理 `/demo-data`

- 利用者・管理者・ドライバーの全画面で共有するブラウザ内データを扱うことを明示する。
- 「初期状態に戻す」と「すべて削除する」を別領域に分け、効果と違いを説明する。
- 削除ボタンを各業務画面へ直接配置せず、共通ヘッダーとデモ入口から本画面へ移動する。
- 初期化・削除の実行前に確認を表示する。削除確認では元に戻せないことと削除対象を明示する。
- 削除成功後は管理者デモ状態を解除し、デモ入口へ戻る。
- 管理者画面内の既存の初期化・削除・終了操作は、管理作業中の導線として維持する。

## 6. 予約・配車管理 `/admin`

### 6.1 画面の目的

既存の予約一覧と予約詳細を利用し、予約を選び直すことなく、依頼確認から配車登録・変更、作業結果の代理登録、再配車まで行う。Ver2初期版では専用の配車管理URLや日別配車盤を設けない。

### 6.2 予約一覧への追加表示

予約状態とは別に「配車状況」の列または文字付きバッジを表示する。

| 配車状況 | 表示条件 |
|---|---|
| 予約取消 | 予約が`cancelled`。過去の一部回収結果を要再配車として表示しない |
| 配車前 | 予約が`received` |
| 配車対象外 | カテゴリーが配車不要 |
| 未配車 | 確定済み・配車対象で有効な配車がなく、直近結果が一部回収・回収不可ではない |
| 要再配車 | 一部回収後、次の有効な配車がない |
| 要対応 | 回収不可後、次の対応が未決定で有効な配車がない |
| 配車済み | `assigned`の配車がある |
| 回収中 | `inProgress`の配車がある |
| 全量回収済み | 直近結果が全量回収 |
| Ver1完了・配車記録なし | 配車対象の予約が`completed`で、移行元に配車記録がない |

予約が`cancelled`・`received`・`completed`の場合を先に判定する。確定予約の配車だけを取り消した場合は再配車可能な「未配車」とし、予約詳細に配車取消履歴を示す。`needsReview=true`の場合は主状態を置き換えず「要再確認」を併記する。予約状態の「受付」「確定」「完了」「取消」は配車状況と別の列で表示する。

### 6.3 一覧の絞り込みと選択

- 日付の対象を「予約日」「配車予定日」から選択し、開始日・終了日で絞り込む。初期値は予約日。配車予定日で絞る場合、配車のない予約は日付条件に一致しない
- 予約状態
- 配車状況
- カテゴリー
- 車両
- 主担当ドライバー
- 受付番号、会社名、担当者名の部分一致検索

「条件をクリア」で初期条件へ戻す。0件の場合は条件に一致する予約がないことと、絞り込みを解除する操作を表示する。予約行を選択すると、既存の予約詳細を開く。

一覧には詳細な住所、電話番号、申告全文を表示しない。配車状況は一覧だけで未配車か配車済みかを判断できる粒度で表示する。

### 6.4 管理画面の注意表示

既存の管理画面の集計領域に、未配車、配車済み、回収中、全量回収済み、要再配車、要対応、要再確認、本日予定、予定日超過・未完了の件数を表示する。件数から対応する予約一覧の絞り込みへ移動できるようにする。予定日超過は、予約が確定のままで、現在の有効配車があればその`plannedDate`、なければ予約の`requestedDate`が日本時間の今日より前の場合とする。予約取消・完了は含めない。

配車期限警告は集計領域の直下に表示する。

| 予約日 | 表示 | 色・優先度 | 選択時の一覧条件 |
|---|---|---|---|
| 今日 | 「本日の未配車がN件あります」 | 赤・至急 | 予約状態=確定、配車状況=未配車、予約日=今日 |
| 明日 | 「明日の未配車がN件あります」 | 赤・至急 | 予約状態=確定、配車状況=未配車、予約日=明日 |
| 2日後 | 「2日後の未配車がN件あります」 | 黄・事前 | 予約状態=確定、配車状況=未配車、予約日=2日後 |

0件の警告は表示しない。一部回収後の「要再配車」と回収不可後の「要対応」は配車期限警告へ含めない。予定日超過の文面には要再配車・要対応を含むことを付記し、単純な配車忘れだけを意味しないことを示す。

別枠で「搬入判断待ち・積み置き中の車両」件数と対象車両、影響する既存の将来配車を表示する。予約完了件数から除外しない。対象の予約詳細へ移動できるようにする。

### 6.5 管理カレンダーの受付・配車確認状態表示

初期表示のカテゴリー「すべて」でも、受付停止・上限超過・配車要確認が発生している日付をカレンダー上で判断できるようにする。配車要確認は配車予定日ではなく、現在の予約日へ表示する。

| 表示条件 | 日付マスの表示 |
|---|---|
| 受付停止のカテゴリーがある | 黄色系の文字付きラベル「受付停止 N」。Nは該当カテゴリー数 |
| 上限超過のカテゴリーがある | 赤色系の文字付きラベル「上限超過 N」。Nは該当カテゴリー数 |
| 未確認の重要変更がある予約がある | 橙色系の文字付きラベル「配車要確認 N件」。Nは予約件数 |
| 複数ある | 成立するラベルを併記 |
| いずれもない | 状態ラベルを表示しない |

カテゴリーを選択した場合は、日付マスへ「予約数／上限数」と、該当時の「受付停止」「上限超過」「配車要確認 N件」を表示する。日付マス全体を警告色だけで塗り分けず、状態名を必ず併記する。カレンダー下部には各ラベルの意味と、「すべて」表示の受付停止・上限超過の数字が該当カテゴリー数、配車要確認の数字が予約件数であることを示す。選択日の予約一覧では対象予約へ「要再確認」を併記する。

日付を選択したときは、選択日詳細の「この日の予約」より前に「カテゴリー別受付状況」を表示する。

| 項目 | 内容 |
|---|---|
| カテゴリー | 蛍光管持込、家具家財撤去、ビン缶回収。カテゴリー絞り込み中は選択カテゴリーだけを表示 |
| 件数 | `現在の予約数 / 設定上限件数` |
| 受付可 | 予約数が上限未満で、受付停止ではない |
| 満枠 | 予約数が上限と同じで、受付停止ではない |
| 受付停止 | 選択日が受付停止、またはカテゴリー上限が0 |
| 上限超過 | 予約数が設定上限を超えている |

受付停止中に既存予約が上限を超えている場合等、複数状態が成立するときは「受付停止」と「上限超過」を併記する。PCでは右側の選択日詳細、スマートフォンではカレンダー直下の選択日詳細へ同じ内容を表示する。

## 7. 予約詳細へ統合する配車・回収仕様

### 7.1 詳細の構成

選択した予約の詳細に、次の領域を上から順に表示する。

1. 予約情報
2. 依頼内容
3. 社内補足
4. 配車登録・現在の配車
5. 作業結果
6. 配車・回収履歴

PCでも別の案件一覧を詳細内へ重複表示しない。予約一覧で対象を選択し、同じ予約詳細内で依頼内容を確認しながら配車入力する。

### 7.2 依頼内容・社内情報

選択した予約について次を表示する。

#### 依頼者・回収先

- 受付番号
- 会社名または依頼者名
- 担当者名
- 電話番号
- 回収先住所
- 到着前連絡等の顧客連絡事項

#### 依頼時申告

- カテゴリー
- 顧客が入力した品目、数量、状況
- 「依頼時申告・目安」の表示

申告量を車両の自動決定や保存拒否に使用しない。

出発前に電話等で確認した数量変更は予約の依頼内容として編集する。現地で判明した回収量は予約内容を上書きせず、作業終了時の「実際の回収内容」に入力する。同日継続中の途中報告は入力を求めない。

#### 社内補足

- 新しい順または古い順のどちらかに固定し、画面内で順序を明示する。初期案は古い順とする。
- 各補足に記録日時、操作者、本文を表示する。
- 1～500文字の追加入力欄と「社内補足を追加」ボタンを置く。
- 保存済みの補足に編集・削除ボタンを置かない。
- 誤記は訂正内容を新しい補足として追加する案内を表示する。

電話報告後に同日中の回収を続けるだけの場合、社内補足の追加は任意であり、画面操作を要求しない。

#### 前回の配車・作業結果

再配車対象では、前回の次の情報を優先表示する。

- 前回の予定日、車両、主担当ドライバー
- 作業開始・終了日時
- 一部回収または回収不可の結果
- 実際の回収内容
- 残り、理由、次回対応のメモ

### 7.3 配車登録・変更

#### 入力項目

| 項目 | 必須 | 入力方法・表示 |
|---|---:|---|
| 予定日 | 必須 | 初回配車は予約日と一致。再配車は調整後の別日も入力可 |
| 開始予定時刻 | 必須 | 時刻入力 |
| 終了予定時刻 | 必須 | 時刻入力。開始より後であること |
| 車両 | 必須 | 有効な架空車両から選択 |
| 主担当ドライバー | 必須 | 有効な架空ドライバーから選択 |
| ドライバー向け指示 | 任意 | 0～500文字。社内補足を自動転記しない |

車両選択肢には車両ナンバー、車両種別、積載量の参考情報を表示する。積載量の参考情報は判断材料であり、自動的な適合保証を示さない。

搬入判断待ち・積み置き中の車両は選択不可とし、理由と「解除時刻未定」を表示する。保留開始前から存在する配車では警告を表示し、その車両での回収開始・作業結果登録を不可とする。別車両への変更と配車取消は可能にする。

#### 操作

- 受付中の配車対象予約では「配車を登録する」を無効表示し、「予約を確定すると配車を登録できます」と常時表示する
- 未配車・要再配車では「配車を登録する」
- 配車済みでは「配車を変更する」
- 入力変更がある場合は「入力を破棄して戻る」
- 配車済みには「配車を取り消す」。回収中には通常の取消ボタンを表示しない

保存時に、予約の最新状態、二重配車、車両・ドライバーの時間重複、版競合を再確認する。重複時は予定日時、車両またはドライバー、重複する予約を表示し、可能な場合はその予約詳細を開く導線を付ける。

配車入力中は、必須項目の未選択、時刻の不整合、車両・主担当ドライバーの時間重複を各入力欄の直下へ赤字で表示する。登録・変更ボタンの近くにも「配車を登録できません」または「配車の変更を保存できません」と理由をまとめ、解消するまで保存ボタンを無効にする。重複する選択肢は一覧から隠さず、車両は「使用中：受付番号 時刻」、担当者は「担当中：受付番号 時刻」と簡潔な理由を併記して選択不可にする。日付を含む詳しい重複内容は入力欄直下と保存操作付近に表示する。PCでは長い選択肢やエラー文があっても3列の入力欄が詳細領域を超えないようにし、スマートフォンでは1列で表示する。赤色だけで状態を伝えず、文章と入力欄の関連付けによって理由を示す。

`assigned`の配車変更は通常の出発前操作として扱い、毎回の未着手確認チェックは設けない。車両・担当者を変更しても同じ配車記録を更新し、配車回数を増やさない。配車取消では既存の確認ダイアログに「作業前の取消」であることを示す。現地で回収済み分があると判明した場合は、通常変更・取消ではなく一部回収の結果登録へ案内する。

### 7.4 作業結果の代理登録

`assigned`または`inProgress`の案件には現在の配車内容を表示し、「作業結果を登録」ボタンを表示する。このボタンは電話報告を受けた配車担当者がドライバーに代わって結果を登録する場合に使用する。開始記録がなくても結果を登録できる。

同日・同じ車両・同じ主担当ドライバーで回収を続ける場合は、ボタンを押さず「配車済み」または「回収中」の現在状態を維持する。「同日継続」「途中報告」「1回目回収完了」等の必須操作は設けない。

### 7.5 要再確認

配車後に重要な予約情報が変更された場合は、次を表示する。

- 「予約内容が配車後に変更されています」の警告
- 最後に変更確認した時点と現在の重要項目の差分。割当時の情報は履歴で確認可能
- 現在の配車内容
- 「変更内容を確認済みにする」ボタン

最新の依頼内容は確認操作前から管理画面とドライバー画面へ反映する。確認済み操作は表示反映や配車の再確定ではなく、配車担当者が変更差分と現在の配車への影響を確認した記録とする。ボタン付近には「変更内容が現在の配車に影響しないか確認してください。必要な場合は先に配車を変更します。」と表示し、必要な配車変更を保存するまでは確認済みにする操作と配車変更を混同しない。回収中の変更では警告を表示するが、自動的に配車を取り消さない。

ドライバー未確認の案件は、日付見出しへ「要確認 N件」、案件欄へ赤い「要確認」と赤系の境界・背景、詳細上部へ「予約・配車内容が変更されています」を表示する。変更された各情報欄へ「要確認」「変更前」「現在」を表示する。「変更内容を確認しました」は、現在の予定日時、回収先、依頼時申告、顧客連絡事項、担当車両、ドライバー向け指示を一通り確認した流れで操作できるよう、これら現在情報の直後かつ「配車後の変更履歴」の前へ配置する。管理者が変更を確認済みにしても、この表示はドライバー本人が確認するまで消さない。ドライバー確認後は赤い表示を消すが、「配車後の変更履歴」は新しい順、最新を初期展開した状態で残す。再変更または主担当ドライバー変更では再び未確認にする。管理画面の配車記録には「ドライバー未確認」または確認日時を表示する。

主担当ドライバーを変更した場合、旧担当者の通常予定から対象案件を直ちに外す一方、旧担当者画面へ「担当変更のお知らせ」を表示する。現在有効なお知らせには受付番号、会社名、以前の予定、現在の担当者、変更日時を示し、予定も同時変更された場合は変更後の予定も示す。確認済みまたは後続変更で確認対象外になった履歴には動的な現在担当を表示せず、「変更前担当者 → 変更後担当者」を当時の記録として固定表示する。旧担当者が「担当変更を確認しました」を押すまでは警告表示を維持し、確認後も担当変更履歴へ残す。新担当者には現在の担当予定として赤い「要確認」を表示する。管理画面には変更前・変更後の担当者と旧担当者の未確認・確認日時を表示する。

同じ案件で担当を複数回変更した場合、通知は履歴ごとに積み重ねず、ドライバーごと・案件ごとに現在有効な通知を1件だけ表示する。担当へ戻ったドライバーの古い「担当から外れました」は確認対象から外して担当変更履歴へ移し、通常予定へ「再担当」「要確認」を表示する。その後再び担当から外れた場合は最新の変更だけを未確認通知とし、途中の変更は「後続の担当変更により確認対象外」として履歴へ残す。履歴データ自体は上書きせず、変更ごとに保持する。

- 変更された欄は薄い赤色系の背景と赤い左境界線で強調する。
- 項目名の近くへ赤地の「要確認」ラベルを表示する。
- 「変更前」は通常の補助色、「現在」は濃い赤の太字で表示する。
- 色だけに依存せず、「要確認」「変更前」「現在」の文字を必ず表示する。
- 日付見出しの「要確認 N件」は集計表示として薄い黄色・橙色系の背景と濃い茶色の文字を使用し、案件欄の赤い「要確認」より警告の強さを抑える。
- 予約日の変更は予定日時と混同しないよう「予約希望日」、住所は「回収先」、回答は「依頼時申告・目安」、連絡事項は「顧客からの連絡事項」の各欄へ表示する。

予約日が変更され、`assigned`の配車予定日と異なる場合は、配車予定日の変更を済ませるまで確認済みにできない。Ver2の既存予約編集では配車の有無を問わずカテゴリーを表示専用とし、「カテゴリーを変える場合は予約取消後に正しいカテゴリーで再受付」と案内する。取消予約からの既存の再受付導線では新しいカテゴリーを選択でき、元予約と新予約の相互履歴を表示する。`assigned`の予約取消では配車も同時に取り消す。`inProgress`は通常取消ができないため、この導線では再受付へ進めない。数量などの申告内容は編集でき、有効配車があれば要再確認の差分として表示する。

### 7.6 再配車

一部回収で作業終了すると、予約を「要再配車」へ表示する。新しい配車は自動作成しない。

1. 要再配車案件を選択する。
2. 前回結果と残りの内容を確認する。
3. 新しい予定日、時刻、車両、主担当ドライバーを入力する。
4. 「配車を登録」で新しい配車記録を作成する。

回収済み分があり、同日中でも車両または主担当ドライバーを替える場合は、この再配車操作を使用する。作業未着手なら現在の配車を変更する。同じ日・同じ車両・同じ主担当ドライバーで続ける場合は再配車しない。

回収不可の案件は「要対応」へ表示する。配車担当者が理由を確認し、再訪が必要と判断した場合は「再配車する」から同じ入力欄を使用する。連絡待ち等で判断できない間は要対応のまま保持し、自動的に再配車を作成しない。

## 8. ドライバー画面 `/driver`

### 8.1 デモ用ドライバー選択

本番認証の代わりに、固定された架空ドライバーを選択する。

- 初期状態ではドライバーを未選択とし、選択を案内する。
- 選択したドライバーIDをブラウザ内に保持してよい。
- 画面に「デモ用の選択であり、本番認証ではない」と表示する。
- 他のドライバーへ切り替える操作を常時提供する。

### 8.2 担当案件一覧

初期表示は本日分とする。表示期間は「今日」「明日」「今後7日」の選択肢と、開始日・終了日の任意指定を提供する。任意期間は開始日を含め最大31日とする。

選択した架空ドライバーを主担当とする`assigned`または`inProgress`の配車だけを表示し、他のドライバーの案件を混在させない。複数日の結果は日付ごとに分け、日付の昇順、各日付内では開始予定時刻、同時刻では受付番号の順にする。本日は見出しで識別できるようにする。未来日を含む場合は「今後の予定は、配車変更により更新される場合があります」と表示する。

各案件に次を表示する。

- 開始・終了予定時刻
- 会社名または依頼者名
- カテゴリー
- 回収先
- 配車状態
- 変更警告の有無
- 担当車両が搬入判断待ち・積み置き中なら、その警告（閲覧のみ）

1日の表示では開始予定時刻の昇順とする。同時刻の場合は受付番号で安定した順序にする。

担当が0件の場合は「この期間の担当案件はありません」と表示し、エラー扱いにしない。

### 8.3 担当案件詳細

次を表示する。

- 受付番号
- 予定時刻
- 会社名または依頼者名
- 回収先住所
- 電話番号
- 配車後の重要変更が未確認の場合は、変更された各情報欄の「要確認」「変更前」「現在」。上部には未確認変更がある旨と配車担当者への連絡案内
- カテゴリーと依頼時申告
- 「依頼時申告・目安」の注意
- 到着前連絡等の顧客連絡事項
- ドライバー向け指示
- 配車後変更の警告
- 担当車両の搬入判断待ち・積み置き中の状態と「配車担当者へ連絡」の案内（閲覧のみ）

社内補足は表示しない。顧客の申告内容とドライバー向け指示は編集できない。

### 8.4 回収開始

`assigned`の案件に「回収開始を記録」ボタンを表示する。開始記録は任意であり、ボタン付近に「開始記録は任意です。記録しなくても作業結果を登録できます。」と表示する。

1. ボタンを押す。
2. 確認ダイアログに対象案件と開始後は通常の配車変更が制限されることを表示する。
3. 「開始を記録」で`inProgress`に変更する。
4. 成功後、開始日時と「回収中」を表示する。

二重押下または再送で開始履歴を重複させない。

### 8.5 同日中の回収継続

電話報告を行った後も、同じ日・同じ車両・同じ主担当ドライバーで回収を続ける場合、ドライバー画面では何も操作しない。

- 配車状態は「配車済み」または「回収中」の現在状態を維持する。
- 積込回数、途中回収量、電話報告の入力を必須にしない。
- 「一部回収」は選択しない。
- 最終的に今回の配車単位を終える時だけ作業結果を登録する。

### 8.6 作業結果登録

`assigned`と`inProgress`の案件に「作業結果を登録」ボタンを表示する。押下すると9章の作業結果ダイアログを開く。`assigned`から保存した場合は開始記録を作らず、直接`completed`へ変更する。

保存後の表示は次とする。

| 結果 | 完了後の表示 |
|---|---|
| 全量回収 | 作業終了。予約も完了 |
| 一部回収 | 作業終了。残りあり・要再配車 |
| 回収できず | 作業終了。要対応 |

終了済み案件から結果を再編集しない。訂正方法はデータ・保存詳細設計で履歴を保つ方式として別途定める。

## 9. 作業結果ダイアログ

予約詳細とドライバー画面で共通の入力規則を使用する。

### 9.1 表示項目

- 対象案件の受付番号、会社名または依頼者名
- 配車予定日、車両、主担当ドライバー
- 開始日時。未記録の場合は「開始記録なし（任意）」
- 回収結果の選択
- 実際の回収内容
- 結果・次回対応メモ

### 9.2 回収結果

| 値 | 画面表示 | 使用条件 |
|---|---|---|
| `allCollected` | 全量回収 | 今回の依頼分をすべて回収した |
| `partiallyCollected` | 一部回収（今回の配車を終了し、残りあり） | 今回の配車単位を終え、別日または別車両・別担当者で残りを回収する |
| `notCollected` | 回収できず | 今回は回収できず、理由確認または再対応が必要 |

同日・同じ車両・同じ主担当ドライバーで引き続き回収する場合はダイアログを閉じ、結果を保存しない旨を補助文で示す。

### 9.3 入力条件

| 項目 | 全量回収 | 一部回収 | 回収できず |
|---|---:|---:|---:|
| 回収結果 | 必須 | 必須 | 必須 |
| 実際の回収内容 | 任意 | 必須 | 任意 |
| 結果・次回対応メモ | 任意 | 必須 | 必須 |

一部回収のメモには、可能な範囲で残っている物、別日対応の必要性、現場上の注意を記録する。回収不可のメモには理由と次に確認すべき内容を記録する。

理由の選択肢は初期版では固定せず、回収できない品目、量の超過、回収前に判明した搬入先の受入停止等を自由記述できるようにする。現地に未回収分が残り、回収済み分もある場合は「回収できず」ではなく「一部回収」を選ぶ。回収後に搬入できなくなった場合は、電話相談により車両へ期間未定で積み置きする可能性があり、この結果区分だけで処理を確定させない。画面操作は14番21章の決定後に設計する。

### 9.4 ボタン

- 「戻る」：保存せず元画面へ戻る
- 「作業結果を保存して終了」：入力確認後に保存する

保存処理中はボタンを無効化し、二重送信を防止する。成功するまで元の案件を作業終了表示へ変更しない。

### 9.5 保存後の案内

- 全量回収：「全量回収として作業を終了し、予約を完了しました」
- 一部回収：「一部回収として作業を終了しました。予約一覧で要再配車と表示されます」
- 回収できず：「回収できずとして作業を終了しました。予約一覧で要対応と表示されます」

全量回収後に搬入できないと分かった場合も予約完了は維持し、14番7.4節の車両保留を別に記録する。作業結果ダイアログで同時に「搬入判断待ち」を選んだ場合は、車両保留の保存まで成功してから完了を表示する。

### 9.6 搬入判断待ち・積み置きの操作

ドライバーは搬入不能を電話で配車担当者へ報告する。配車担当者は代理で回収結果を登録する時、または回収済み案件の詳細から「搬入判断待ち」を登録できる。ドライバー自身が結果を登録した場合も、保留操作は配車担当者が別に行う。対象車両、搬入できない理由、電話相談の状況を表示・入力し、解除予定日時は求めない。電話相談で積み置きが決まったら「積み置き中にする」、搬入または別方法で積載が解消したら理由を入力して「保留を解除する」を行う。ドライバー画面では保留状態を表示するが、判断結果の入力操作は設けない。記録日時・操作者と相談メモは対象予約の詳細履歴から確認できる。保留中は予約・配車の完了表示を変更しない。二重登録、古い版からの変更、保存失敗では車両状態を変更せず入力を保持する。

## 10. 状態別の表示と操作

| 予約・配車の状態 | 主な表示 | 許可する主操作 |
|---|---|---|
| 予約が受付 | 配車前 | 予約内容の確認。配車登録不可 |
| 確定・未配車 | 未配車 | 配車登録 |
| 配車済み | 配車内容、開始記録は任意 | 通常の配車変更、確認後の配車取消、回収開始記録、作業結果登録 |
| 回収中 | 開始日時、作業中 | 作業結果登録。通常の配車取消は不可 |
| 回収中・同日継続 | 回収中のまま | 追加操作なし |
| 一部回収で作業終了 | 前回結果、要再配車 | 新しい配車登録 |
| 回収不可で作業終了 | 理由、要対応 | 対応判断後に「再配車する」から必要なら再配車 |
| 全量回収で作業終了 | 全量回収、予約完了 | 履歴閲覧 |
| 全量回収済み・搬入判断待ち／積み置き中 | 予約完了と車両保留を別表示 | 相談結果の記録、積み置き中への変更、保留解除、履歴閲覧 |
| 一部回収済み・搬入判断待ち／積み置き中 | 要再配車と車両保留を別表示 | 相談結果の記録、積み置き中への変更、保留解除、履歴閲覧 |
| 予約取消 | 取消 | 履歴閲覧 |
| 配車だけ取消・予約は確定 | 未配車、配車取消履歴 | 新しい配車登録、履歴閲覧 |

配車対象の予約では従来の「完了」ボタンを表示せず、全量回収の作業結果から予約を完了させる。配車対象外の予約では従来の完了操作を維持する。

## 11. 確認ダイアログ

| 操作 | 確認内容 |
|---|---|
| 配車取消・配車済み予約の取消 | 対象、予定、作業前の取消として扱うこと。回収済み分があれば結果登録へ案内 |
| 回収開始記録 | 対象、任意の記録であること、開始後は通常の配車変更・取消が制限されること |
| 作業結果保存 | 結果、予約への影響、要再配車または要対応になるか |
| 要再確認を確認済みにする | 変更差分を確認したこと。配車変更そのものではないこと |

単純な一覧選択、絞り込み、同日継続には確認ダイアログを表示しない。

## 12. 入力検証とエラー表示

### 12.1 配車入力

- 必須項目は保存時だけでなく項目付近にも不足を表示する。
- 終了予定時刻が開始予定時刻以前なら保存しない。
- 同じ予約に有効な配車が存在する場合は、新規配車を保存せず既存配車を表示する。
- 車両またはドライバーが重複する場合は、重複する予定の日時と案件を表示する。
- 予約が取消・完了へ変わっていた場合は、入力を消さず保存停止理由を表示する。

### 12.2 作業結果

- 結果未選択では保存しない。
- 一部回収で実際の回収内容または結果メモが空の場合は保存しない。
- 回収不可で結果メモが空の場合は保存しない。
- `assigned`または`inProgress`から作業結果を登録できる。
- `needsReview=true`は配車担当者の確認管理に使用し、回収開始記録と作業結果登録を妨げない。
- `completed`または`cancelled`の配車へ結果を重ねて保存しない。

### 12.3 保存失敗・競合

- 保存中は処理中表示を出し、操作対象を二重送信できないようにする。
- 保存失敗時は成功メッセージを表示しない。
- 入力内容を可能な限り保持し、「再試行」または「最新状態を確認」を示す。
- 版競合時は自動上書きせず、最新状態と自分の入力を区別して表示する。
- 他タブで初期化・削除された場合は古い参照を破棄し、最新のデモ状態へ戻す。

## 13. ドライバー・車両管理

### 13.1 ドライバー管理 `/admin/drivers`

#### 13.1.1 画面の目的

配車で選択するドライバーを管理する。勤怠管理との直接連携は初期版では行わず、同じブラウザ内の`drivers`ストアへ保存する。予約・配車管理のヘッダーから移動し、同画面へ戻る導線を置く。

#### 13.1.2 一覧

- 状態、ドライバーコード、氏名、備考、操作を表示する。
- 初期表示では有効・無効を両方表示し、無効なドライバーを非表示にできる。
- 削除操作は設けず、過去の配車記録を維持する。

#### 13.1.3 登録・編集

- 登録項目は氏名と備考とし、氏名だけを必須とする。表示名は設けず、各画面で氏名を使用する。
- 氏名は80文字以内、備考は500文字以内とする。
- コード入力欄は設けず、既存最大番号の次を`DRV-0001`形式で自動採番する。無効化した番号は再利用しない。
- 将来の勤怠管理連携で同一人物を識別できるよう、自動採番したコードは登録後に変更しない。
- 有効なドライバーだけを新規配車とドライバー画面の選択肢に表示する。

#### 13.1.4 無効化

- 無効化前に確認を表示する。
- `assigned`または`inProgress`の配車が1件でもある場合は保存せず、配車変更または取消を案内する。
- 無効化後も一覧と過去の配車記録には氏名を残し、再び有効化できる。

### 13.2 車両管理 `/admin/vehicles`

#### 13.2.1 画面の目的

配車で選択する車両を管理する。予約・配車管理のヘッダーから移動し、同画面へ戻る導線を置く。車両保留の判断・解除は予約詳細で行い、車両管理では状態確認だけを行う。

#### 13.2.2 一覧

- 状態、車両コード、車両ナンバー、車種、積載参考情報、用途・注意事項、搬入判断待ち・積み置き状態、操作を表示する。
- 初期表示では有効・無効を両方表示し、無効な車両を非表示にできる。
- 削除操作は設けず、過去の配車記録を維持する。
- 車両ナンバーを各画面の主表示とし、旧データで車両ナンバーがない場合だけ旧表示名を使用する。

#### 13.2.3 登録・編集

- 登録項目は車両ナンバー、車種、積載参考情報、用途・注意事項とし、車両ナンバーと車種を必須とする。別の表示名は設けない。
- 車両ナンバーは30文字以内、車種は50文字以内、積載参考情報は200文字以内、用途・注意事項は300文字以内とする。
- コード入力欄は設けず、既存最大番号の次を`VEH-0001`形式で自動採番する。無効化した番号は再利用しない。
- 自動採番した車両コードは登録後に変更しない。
- 車両ナンバーは表示上の空白・ハイフンの違いを除いて同一と判断し、重複登録を防止する。
- 車両ナンバーの訂正や同一車両の番号変更は編集で行う。別車両への入替では既存車両を無効化し、新しい車両として登録する。
- 有効で保留中でない車両だけを新規配車の選択対象とする。

#### 13.2.4 無効化

- 無効化前に確認を表示する。
- `assigned`または`inProgress`の配車が1件でもある場合は保存せず、配車変更または取消を案内する。
- 搬入判断待ちまたは積み置き中の場合は保存せず、対象予約で保留解除が必要なことを案内する。
- 無効化後も一覧と過去の配車記録には車両情報を残し、再び有効化できる。

## 14. 空状態・読込状態

| 状況 | 表示 |
|---|---|
| 予約未選択 | 予約一覧を表示し、選択すると予約詳細を開く |
| 一覧0件 | 条件に一致する案件がないことと条件解除ボタン |
| 指定期間の担当0件 | 正常な空状態として「この期間の担当案件はありません」 |
| 社内補足0件 | 「社内補足はまだありません」 |
| 過去の配車0件 | 「過去の配車履歴はありません」 |
| 読込中 | 対象領域に読込中表示。前回案件の内容を残したまま別案件として見せない |
| 読込失敗 | 再試行導線と、保存済みデータを削除しない旨 |

## 15. スマートフォン表示

### 15.1 予約・配車管理

予約一覧から予約を選択して既存の予約詳細を開く。予約詳細では、予約情報、依頼内容、社内補足、配車、作業結果、履歴を縦に表示する。詳細から一覧へ戻る操作を設け、ブラウザの戻る操作だけに依存しない。詳細内の領域を移動しても配車入力を保持する。

### 15.2 ドライバー画面

- 主要ボタンのタップ領域を十分に確保する。
- 任意の「回収開始を記録」と「作業結果を登録」を視覚的に区別し、開始記録を必須と誤認させない。
- 作業結果の選択肢には長い説明を併記し、誤って一部回収を選ばないようにする。
- 住所、指示、電話番号は横スクロールせず読めるようにする。

## 16. アクセシビリティ

- キーボードだけで一覧選択、入力、ダイアログ操作を行えるようにする。
- フォーカス位置を視覚的に示す。
- ダイアログ表示時はダイアログ内へフォーカスを移し、終了時は呼出元へ戻す。
- 入力エラーを色だけで表さず、項目名と理由を文字で示す。
- 状態バッジに読み上げ可能な名称を設定する。
- 見出し順を画面構造と一致させる。
- 保存成功・失敗を読み上げ可能な通知領域へ表示する。

## 17. 初期版の画面対象外

- 地図、経路、GPSの表示
- 車両位置のリアルタイム追跡
- 途中の積込回数・運搬回数の記録
- 同日継続の登録ボタン
- 写真、署名、添付ファイル
- 実績数量の品目別数値入力
- 車両・ドライバーの削除、一括取込、勤怠管理との自動同期
- 本番ログイン、権限別メニュー制御
- 顧客への通知送信画面
- マニフェスト、請求、売上管理画面
- 専用の配車管理URL、日別・車両別の配車盤

## 19. 次の設計作業

Ver2データ・保存詳細設計書は16番、Ver2テスト仕様書は17番、Ver2実装指示書は18番文書として作成済みである。次は18番文書に従って実装する。16番文書では次を確定した。

- 配車、社内補足、履歴の型と索引
- 作業結果ごとの必須項目
- 任意の回収開始記録、開始記録なしの作業終了、予約完了、再配車のトランザクション
- 配車担当者による代理登録時の操作者記録
- 冪等キー、版競合、再送時の扱い
- 初期データと画面状態の対応
